1. ¿Qué ocurre al adjuntar un archivo?

Ingesta y extracción

La plataforma recibe el archivo y puede extraer texto, tablas, imágenes, fotogramas o audio según formato, modelo, herramientas y plan.

Selección de contenido

No siempre se envía íntegro al modelo: algunos productos extraen, fragmentan, indexan o recuperan solo partes relevantes.

Razonamiento y respuesta

El modelo responde sobre lo que efectivamente recibe o recupera. Si se pierde estructura o información visual, pueden producirse omisiones.

Revisión

Contrasta citas, páginas, cifras, fórmulas, capturas y decisiones con el archivo original. Una respuesta convincente no verifica el documento.

Principio esencial: tamaño del archivo (MB), número de páginas, duración del vídeo y tokens de contexto son medidas diferentes. No hay conversión fija entre ellas.

3. Estrategias para muchos archivos

  1. Inventario: registra nombre, formato, fecha, versión, fuente y propósito de cada archivo.
  2. Priorización: separa archivos normativos, datos base, borradores e históricos.
  3. Fragmentación: divide documentos grandes por capítulo, asunto o fecha, preservando títulos y números de página.
  4. Resumen verificable: conserva hallazgos con referencia exacta (documento, página o sección), dudas y cambios.
  5. Recuperación: cuando hay muchos documentos y consultas recurrentes, considera búsqueda documental/RAG; comprueba que encuentre los pasajes relevantes.
  6. Validación: no sustituyas tablas originales, archivos maestros ni decisiones formales por resúmenes.

Adjuntar directamente

Conveniente para pocos archivos pequeños y una consulta concreta, cuando caben en el contexto efectivo.

Extraer y resumir

Conveniente para documentos extensos o reuniones; conservar evidencias y estructura del original.

Proyecto o biblioteca

Conveniente para material de trabajo persistente: guías, instrucciones y archivos compartidos. Confirmar cómo recupera cada plataforma.

RAG / búsqueda documental

Conveniente para colecciones grandes. Busca fragmentos y los aporta al modelo; no equivale a «entrenar» un modelo ni elimina los errores.

4. ¿Qué es RAG?

Retrieval-Augmented Generation o generación aumentada por recuperación: un sistema busca información en una colección y entrega pasajes relevantes al modelo para construir una respuesta.

Consulta → búsqueda en archivos → recuperación de fragmentos → respuesta con referencias → comprobación. Un sistema RAG necesita evaluarse: puede recuperar un fragmento equivocado, omitir uno crucial o responder mal incluso con una fuente correcta.

RAG no es memoria autobiográfica ni aprendizaje del modelo: utiliza una fuente externa, y su contenido puede cambiar sin reentrenar los parámetros. Algunas plataformas de «proyectos» usan recuperación, otras incluyen materiales directamente o combinan enfoques; no asumir su implementación.

6. Ejemplo: elaborar una propuesta desde archivos

Escenario ficticio: una reunión de capacitación produce un audio, una transcripción TXT, bases en PDF, un programa Word y un README Markdown.

  1. Transcribir el audio, verificar nombres y acuerdos en los fragmentos importantes.
  2. Usar TXT/Markdown para el registro de decisiones, incluyendo origen y fecha.
  3. Revisar requisitos del PDF citando páginas; si tiene diagramas, verificar lectura visual.
  4. Editar el programa en DOCX conservando estilos y una copia de control.
  5. Al abrir un nuevo chat, transferir un resumen verificado, versiones y archivos indispensables.

Continuar con la simulación de cuatro semanas o abrir el generador de traspaso.
